Updated 15 September 2026. Branch: `feat/personalized-coaching-mwg`; worktree: `D:/BONYAN-experience`. Changes are local and uncommitted.

1. **Changes.** Connected goal selection, guided setup, body assessments, profile, coaching score, history, notifications, avatar milestones and training. Added cool translucent cards, a legible cropped BONYAN mark, restrained transitions respecting reduced motion, keyboard-aware scrolling, safe Back fallbacks, bilingual plan preparation/success states and recoverable errors.
2. **Main modules.** Mobile `features/auth/components/{CoachingJourney,AssessmentEditor,ProfileOverview,CoachingUI,PerformanceFields}.tsx`, `journey.ts`, `coachingCopy.ts`, session/draft storage, `core/notifications`, `core/navigation/safeNavigation.ts`, shared `BrandMark`, `NotificationBell`, `MotionReveal` and `AvatarJourneyCard`, plus home/training/InBody screens. API `core/{assessment_integration,profile_integration}.py`, users schemas/repository/service/scoring, training rules/planner, InBody upload service, and provider configuration/adapters.
3. **Onboarding.** Welcome → name/optional personal details → goal → goal-specific focus or preparation category → manual/confirmed InBody measurements → experience → schedule/equipment → optional performance targets → summary. Drafts survive reload; account changes clear private cached data and drafts. Body assessment remains optional and can be added later.
4. **Dynamic questions.** General fitness and fat loss ask about running; strength and muscle building ask about push-ups; military preparation asks about running, push-ups and pull-ups; fat loss includes a personal weight target. Shared answers survive goal changes, while incompatible preparation and weight-target fields are cleared.
5. **Military preparation.** Added `military_preparation` alongside all existing goals. Generic military-college/other/undecided categories and an optional target date avoid inventing institutions or entry standards. Training uses strength-endurance repetition/rest rules and preparation day labels. This is not a validated institution-specific preparation curriculum.
6. **Manual vs InBody.** Manual height/weight and optional body fat are validated and persisted. InBody selection reads a real, owned, confirmed scan, converts supported units and rejects invalid/missing weight. No extracted numbers are invented. Explicit re-upload of previously failed identical content retries processing using its existing record; confirmed duplicates retain deduplication.
7. **Score formula.** Version `personal-targets-v1`: reported ability ÷ personal target, capped to 0–100. Consistency is reported active days ÷ planned days. Weight progress is `(first weight − current weight) / (first weight − target weight)` when the target is below the baseline. Available dimensions are weighted and renormalized; missing data remains missing, with separate coverage. Military weights: running 40%, push-ups 30%, pull-ups 10%, consistency 20%; strength: 65/35 push-ups/consistency; hypertrophy: 50/50; fat loss: weight 50%, consistency 30%, running 20%; general fitness: running/consistency 50/50. This is a transparent coaching indicator, not a medical or military admission score.
8. **Score updates.** Profile/target changes and new assessments recompute the current score and store historical snapshots. Historical scores retain their original context. Scores currently use self-reported performance and active days; they do not automatically aggregate completed workout logs or expire stale inputs.
9. **Profile.** Shows actual goal/preferences, completion, current assessment and score. Editing retains existing optional birth date, sex, units and timezone settings. Training generation now takes goal, experience, weekly days and equipment from the saved profile instead of a fixed request. Changing these inputs archives the old active plan without deleting workouts.
10. **History.** Owner-scoped, paginated immutable assessment/profile snapshots; idempotent saves serialize on the account row, including concurrent requests. Existing manual measurements are imported with original timestamps and no fabricated historical score. Older confirmed InBody reports remain available through existing InBody history and can be selected into the connected assessment timeline.
11. **Backend compatibility.** Existing goals/routes remain. Added `GET /api/v1/me/assessment`, `GET /api/v1/me/history`, `GET /api/v1/me/history/{id}`, and `POST /api/v1/me/assessments`. Optional coaching preferences are additive; partial preference updates preserve unspecified values. History participates in account deletion. Other users' history and reports return 404.
